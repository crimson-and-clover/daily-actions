# Code Review Guide

## 1. 语言规范
- 所有代码审查（包括总结报告、代码行内 Comments 与建议）**必须全部使用简体中文**输出。

## 2. 审查模式与节制规范 (Guardrails)
- **严格纯静态逻辑审查**：聚焦于本次 Diff 的变更代码及核心领域逻辑，重点关注潜在的逻辑 Bug、性能问题、安全性隐患与异常处理缺失。
- **严禁编写测试脚本实证**：审查以静态研判为主，严禁编写大量临时测试脚本运行实证，严禁进行穷举式边缘用例测试。
- **严禁向未修改的历史代码过度发散**：不要向无关的上下游历史模块无节制延伸扩展。
- **存疑问题以提示性建议提出**：若发现疑似缺陷但无法在静态研判中直接确证，严禁深陷实证死循环，直接在评审意见中作为“提示性建议 (Suggestion)”提出。
- **快速收敛并提交**：主智能体交互必须保持克制，严格在 5-10 轮交互内调用 GitHub API 提交 Review，严禁长时间处于探索排查状态。
